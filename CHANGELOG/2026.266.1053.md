# 2026.266.1053 — feat: relocate the check-substrate R10 bed from opencharly/charly

## Summary of changes

Relocate the `check-substrate` R10 witness bed — its `kind:local` template and the disposable `eval-vm` it nests inside — out of `opencharly/charly`'s `charly.yml` and into the plugin's owning repo, `opencharly/plugin-substrate`.

WHY: an R10 bed must live in the repo that owns the behaviour it witnesses. The check-bed runner's dev-tree override (`proc.SelfSuperprojectOverridePair`) points the bed PROJECT's own superproject at the local tree; a witness parked in `charly/` never exercises the foreign-owned plugin candy as in-development code. Relocated here, the bed is owned beside the plugin it proves.

Per-file (against `origin/main` at `ce7e1c4`, head `911343c`, `git diff --stat origin/main...HEAD` = 81 insertions, 3 deletions):

- **`charly.yml` (+64/−2)** — adds the `eval-vm` disposable Arch cloud-image VM (a LOCAL copy: the bed's nested member needs a same-project template ref and this repo does not import `main`); adds the bare `check-substrate-app` `kind:local` TEMPLATE, which composes `@github.com/opencharly/layer-check-substrate-layer:v2026.240.0118` (drops `/etc/check-substrate-marker` in the guest); adds the `check-substrate` `vm: {from: eval-vm}` bed with the nested `check-substrate-member` local DEPLOY whose plan asserts `/etc/check-substrate-marker` in the GUEST. Bumps the schema stamp `version: 2026.232.0520 → 2026.249.2125` and sweeps the now-false "declares no entities of its own" header comment.
- **`.github/workflows/deploy.yml` (+1/−1)** — **CI pin bump `v2026.238.1242 → v2026.256.1316`** (the real diff value). This is a supply-chain surface and is listed explicitly: the `candy` CI job builds the validating `charly` binary from this pinned source, so the pin must be new enough to accept the config-schema stamp this PR introduces. `v2026.238.1242` predates `version: 2026.249.2125`, so its `charly box validate` would reject the stamp as newer than it supports; `v2026.256.1316` is newer than the stamp and accepts it.
- **`.gitignore` (+16/−0)** — new file; standard generated-artifact rules: `.build/`, `.containerignore`, `.dockerignore`, `.check/`, `output/`, editor scratch (`*.swp`, `*~`), and `charly migrate`'s `*.bak`/`*.bak.*` rollback backups.

**Reconciliation of the two version numbers** (raised by the reviewer): `charly.yml` `version: 2026.249.2125` is the **config-schema CalVer stamp** — the head the R10 binary supports (the binary reports `max 2026.249.2125`; `charly migrate` on a newer host config errors `schema 2026.261.1747 is newer than this charly supports (max 2026.249.2125)`). `v2026.256.1316` is the **charly SOURCE version** the CI workflow checks out to build its validating binary. They are independent namespaces and need not be equal; the CI pin is deliberately ≥ the schema stamp so the CI `validate` accepts it.

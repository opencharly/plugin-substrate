# 2026.318.1621 — test(vm): move the body behaviour test with the body

## Summary

opencharly/spec#304 unit 8, the coverage half. The vm body lives in this plugin CUE module since plugin-substrate#42, and its ONE behavioural test still called the spec package defValue against the shipped schema. It moves HERE, before the contract leg deletes the vm body, so the coverage never lapses. **Its lifecycle in full:** the `spec` copy (`TestVmBackendKrunCrossRules` in `schema/engine_vocab_and_vm_backend_test.go`) stays where it is until the contract leg deletes the `#Vm` it compiles against; that leg is tracked as the next unit-8 item on `opencharly/spec#304`, and the coordination pair is posted on this PR and on that issue.

**The test, unchanged in behaviour:** TestVmBackendKrunCrossRules - three accepted krun shapes (container_disk, the krun knobs, and a bootc source), five libvirt/qemu-only fields that must be rejected NAMING the field they reject (libvirt, autostart reported at the backend rule, firmware, machine, cloud_init), a non-OCI source rejected, and a positive control proving the same fields are legal under backend libvirt - so the rejections are about the backend, not the fields.

**The harness is the point.** It composes exactly what the host gate composes - the spec base and this plugin served unit - and compiles every literal in the def own CUE context. The allErrors flattener moves with it because the assertion is about the error NAMING, and the CUE top-level Error() truncates to (and N more errors).

**Why only one test:** measured, this kind has no value-gate tests in spec (unlike pod/local/kubevirt), and its other vm-named test files - vm_iso_source_test.go, vm_container_disk_source_test.go, vm_box_metadata_test.go - exercise the KEEPERS (VmSource, VmBoxSource) that stay in the contract, so they stay with them.

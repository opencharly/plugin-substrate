# 2026.241.1111 — refactor(status): enumerate the ledger via kit, not a second YAML parser

## Summary

`plugin-substrate#3` migrated this collector onto the relocated `ledger:` section by adding two local helpers, `ledgerDeployIDs` and `ledgerCandyNames`. Each opens the per-host `charly.yml` and unmarshals its own inline `ledger:` struct, so the ledger's on-disk shape ended up parsed in **two repos** — `sdk/kit` and here — with any change to that section having to move in lockstep across both.

This PR does two things:

1. **Removes the duplicate parser.** Both passes call `kit`'s canonical enumeration, which shares `readLedger` with every other ledger accessor and carries its own tests. The `gopkg.in/yaml.v3` import falls out of the file entirely, which is the tell that the duplication is gone rather than relocated.

2. **Makes a malformed ledger loud on both passes.** This is the part an earlier revision of this PR got *wrong*, and it is worth stating plainly: moving to the non-strict `kit.ListDeployIDs` / `ListCandyNames` silently dropped an error path, because they return a bare slice. An unparseable `charly.yml` would have become "no candies" instead of a parse failure. I claimed that substitution was "behaviour-preserving by construction"; it was not, and the review was right to block it. `kit.ListDeployIDsStrict` / `ListCandyNamesStrict` (opencharly/sdk#184, tagged `v0.2026241.1051`) draw the distinction — absent is nil, unparseable is an error naming the path — and both passes now propagate it.

**This also removes a pre-existing asymmetry rather than preserving it.** Before this PR the deploy pass swallowed its error while the candy pass propagated:

```go
deployIDs, err := ledgerDeployIDs(paths)
if err != nil {
    return spec.SubstrateStatusReply{}, nil            // swallowed
}
candyNames, err := ledgerCandyNames(paths)
if err != nil {
    return spec.SubstrateStatusReply{}, fmt.Errorf(...) // propagated
}
```

So a malformed ledger was already loud one way and silent the other, for no stated reason. Restoring the old code as-is would have kept that.

Why this matters here specifically: printing "nothing deployed" for a file that could not be parsed is the exact failure this collector already shipped once — the relocation left `paths.Deploys == ""`, `os.Stat("")` returned `ENOENT`, and the availability guard read a *relocated* ledger as an *absent* one.

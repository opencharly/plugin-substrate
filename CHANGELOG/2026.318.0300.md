# 2026.318.0300 — feat(kubernetes,kindcluster): own the kind bodies — the two move into the plugin's CUE module

## Summary

`opencharly/spec#304` unit 5, leg 1 (the producer): the `kubernetes` and `kindcluster` entity bodies move from the contract module into the CUE module of the plugin that **serves** them, and each `kind` capability declares its gate def in the same change.

**WHICH plugin, measured.** `spec#304`'s table names `plugin-kube`. Measured: `plugin-substrate`'s `substrateWords` carries `kubernetes` AND `kindcluster`, while `plugin-kube`'s `providers:` are `verb:kube`, `deploy:kubernetes`, `deploy:kindcluster` — the DEPLOY targets, not the kinds. The same correction `pod` (unit 3) and `local` (unit 4) each needed; it is recorded on the tracker.

**What moved, and what stayed.** The bodies travel with their own sub-defs: `#Kubernetes` + the five `#Kubernetes*` policy sub-defs + the four vocabulary tables (all cited ONLY by this body) and `#Kindcluster`. What stays in the contract is cited as `schema.#…`: `#Step`, `#Deploy`, `#DeployValue`, `#EngineName`, `#KubernetesDeploy`.

**What came with the bodies, swept rather than copied.** The new files' comments name this five-file module, never the contract's layout, and the `@vocab` owner is `plugin-substrate` on every table in both files — the contract carried `spec` and a "00_common.cue" note that exists nowhere here.

**The import moved, and that is load-bearing.** `kindcluster.cue` sorts BEFORE `local.cue`, so the module's single contract import moves out of `local.cue` into the file that now sorts first — `schemaconcat.ConcatSchema` concatenates a module's files in sorted order and a CUE `import` must precede every declaration. Every affected file's header states the order.

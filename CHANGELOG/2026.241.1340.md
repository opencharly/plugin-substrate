# 2026.241.1340 — perf(status): direct per-host config read + bulk ledger read

## Summary

- **`status_flat.go`**: `loadFleetConfig` reads the per-host charly.yml DIRECTLY (a lightweight yaml.Unmarshal into the FleetConfig) instead of the full LoadUnified project walk — measured ~197MB of allocation per load (the GC pressure that dominated `charly status`). The per-host config is a small file with no imports; the direct read is placement-invariant.
- **`status_local.go`**: `collectLocalStatus` reads the FULL ledger maps in ONE read (`kit.ReadLedger`) instead of re-reading the 310KB config once per record (measured: 186 reads per status run).
- Pins sdk v0.2026241.1311 + spec v0.2026241.1322 (the status-caches tags).

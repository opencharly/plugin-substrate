# 2026.331.1555 — fix(schema): give the provider declaration a plugin-scoped name instead of #SubstratePlugin

## Summary

The plugin's served schema declared **`#SubstratePlugin`**, a name the **pod kind's plugin also declares**. The host splice unifies same-name definitions across sources, so the merged shape no longer matched either plugin's authored input and the loader refused the **whole deploy plugin set**:

```
charly: error: command "deploy": load deploy plugins: plugin "plugin-substrate": its served schema
  re-declares #SubstratePlugin, already declared by plugin "kind:pod" — CUE UNIFIES same-name
  definitions across sources ... Give the def a plugin-scoped name ...
```

Fixed by giving the provider declaration a **plugin-scoped name, `#SubstrateProvider`**.

Why that name and not `#<Word>Input`: the convention names a plugin's typed **input** def, and this plugin declares no `plugin_input` (its authored input is the pass-through CLI grammar — the file's own header says so). This def documents the provider's kind/command/verb words on the served surface.

So: **no production code** keys on it; sdk and spec do not mention it; two hits in charly are a historical CHANGELOG entry (immutable history, left alone) and **one test** (`kind_value_composed_test.go`) that resolves the def by name. That test moves with the consumer wave — the charly leg that adopts this release updates it to `#SubstrateProvider` in the same change, because on `main` today the old name is still what the plugin serves.

Files: `schema/substrate.cue` (the def), `plugin.go` (the doc comment that named it), `schema_serve_test.go` (the guard).

The serve test now pins BOTH directions, so the collision cannot silently return:

```go

```

**Red arm:** the negative assertion fails on the pre-rename schema (it contains `#SubstratePlugin` and not `#SubstrateProvider`), which is the state that produced the loader error.

### Spike

**RCA claim:** the defect is a definition-name collision on the served surface, not a schema-content error.

**Candidates:**

- **A. Rename the def to a plugin-scoped name (chosen).** Instrument: the plugin's serve test on the composed schema, asserting the old name is absent; a consumer run of `charly deploy add` is the end-to-end proof (posted on opencharly/plugin-substrate#53 and opencharly/charly#1307 — the A/B there shows the pre-pin binary exit 0 and the wave's binary exit 1 with this exact error). **Works.**
- **B. Delete the def entirely.** Rejected by inspection: it is the plugin's declaration/documentation surface (the kinds/commands/verbs it serves) and the serve test's non-empty-schema contract is built on it; deleting it would remove documentation rather than resolve the collision.
- **C. Make the host tolerate a duplicate def name.** Rejected: CUE unifies same-name defs, so the merged shape is *wrong* rather than merely warned about — every plugin sharing the name then rejects its own input (the loader's own message states this). A tolerant host would move an unresolvable merge into every consumer.

**Winner:** A. **RCA verdict:** confirmed — the name collision is the whole mechanism.

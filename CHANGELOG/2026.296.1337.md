# 2026.296.1337 — feat(substrate): declare the deploy selectors on every substrate trait (#30)

## Summary

`substrateTraits` declared every `#DeployTraits` field except `Selectors`, so the hosting rule's DATA half was absent: nothing told a loader that `engine:`/`rootful:` belong on a pod deploy and `backend:` on a vm deploy. This change declares them:

| Substrate | `Selectors` | Why |
|---|---|---|
| `pod` | `engine`, `rootful` | the only engine substrate; `ResolvePodEngine` reads the engine level and `ResolveContainerdTarget` the rootful level |
| `vm` | `backend` | the only VM-backend substrate; `ResolveVmBackend` reads it |
| every other word | none | the canonical table names selectors only for pod and vm |

**No selector word is spelled in Go.** The word is taken from the `spec.Deploy` field's own yaml name (`Engine` → `engine`, `Backend` → `backend`, `Rootful` → `rootful`), so a contract rename is a loud init panic instead of a silent drift. Two tests hold the declaration to the producers: every declared word must be a member of `#DeployTraits.selectors`'s closed vocabulary in the spec module's embedded schema, and it must be honoured by the sdk resolver that owns that level (behavioural probes against `ResolvePodEngine` / `ResolveVmBackend` / `ResolveContainerdTarget`).

Pins: `github.com/opencharly/spec v0.2026296.1036`, `github.com/opencharly/sdk v0.2026296.1207`.

Diff surface: `plugin.go` (the two declarations), `selectors.go` (the spec-derived vocabulary), `selectors_test.go` (the two drift controls), `go.mod`/`go.sum` (the pin bump).

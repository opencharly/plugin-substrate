# 2026.269.0703 — feat(kubevirt): declare the kubevirt substrate's own venue value

feat(kubevirt): declare the kubevirt substrate's own venue value

The trait table is the single source the kernel stamps onto `node.Descent` and every
venue-consult site reads. kubevirt now declares `Venue: "kubevirt"` (not `"ssh"`): it is
a cluster-managed `VirtualMachine` CR whose lifecycle an out-of-process plugin owns, so a
bare `Venue == "ssh"` test downstream names the host-libvirt vm and nothing else.

> **Companion to opencharly/spec#168** (the venue enum + descent mapping). This PR is the
> PRODUCER half; spec#168 is the CONTRACT half. Landing order is **CONTRACT-first**:
> spec#168 merges + tags, THEN this trait row can be live — the reverse would feed the new
> `kubevirt` venue into an OLD `DescentFromTraits`, whose default arm sets
> `transport: "none"` (the kubevirt node would lose its ssh hop). The `IsVmVenue` predicate
> keeps its `ExclusiveVenue` guard, so the *predicate* is order-safe either way.
>
> spec#168 has merged + tagged (`v0.2026269.656`), so this PR now carries that spec pin
> bump and builds at its own `go.mod` (`GOWORK=off`).

## Summary of changes

- `candy/plugin-substrate/plugin.go` — `substrateTraits["kubevirt"].Venue`: `"ssh"` →
  `"kubevirt"`.
- `candy/plugin-substrate/venue_table_test.go` — new `TestSubstrateTraits_VenueTable`
  pins every declared venue and fails if the kubevirt row reverts to `"ssh"`.
- `candy/plugin-substrate/go.mod` / `go.sum` — spec pin bumped
  `v0.2026268.2214 → v0.2026269.656` (the tag spec#168 minted), so the committed

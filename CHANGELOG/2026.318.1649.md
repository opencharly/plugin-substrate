# 2026.318.1649 — fix(vm): the resolve arm decodes straight into the envelope

## Summary

opencharly/spec#304 unit 8: the vm body lives in this plugin CUE module since plugin-substrate#42, and the resolve arm decoded it into the contract Go type `spec.Vm` before a fourteen-field hand copy into the envelope.

**This is a FIX, not a no-op.** Round 1 caught the body claiming the projection was unchanged; it is not. The envelope carries `Krun` (`*VmKrun`), and the removed fourteen-field literal never copied it — so the hand copy silently dropped a krun guest's knobs. **The arm now takes the local.cue pattern**: the `#ResolvedVm` envelope carries exactly the body fields (source, disk_size, ram, cpu, machine, firmware, backend, autostart, network, ssh, cloud_init, libvirt, krun, plan, snapshot) plus raw — the envelope is the body minus `mcp_provide` — so the arm unmarshals the authored bytes straight into it.

**The proof is the plant.** `TestResolveVm_FieldCopy` now names EVERY envelope field and asserts it. Planted back to the old hand copy it fails: `krun did not survive the projection — the former hand copy dropped it: <nil>`; restored byte-identical, the suite is green.

**No consumer remains**: `grep -rn spec.Vm --include=*.go` over this module returns FIVE hits and every one is a comment — in plugin.go, resolve.go, resolve_test.go and validate_vm.go; no Go code reads the authored type (the paste is below).

# 2026.273.0433 — fix(substrate): adopt the sdk ctx requirement on the deploy-config family

## Summary

Adopt the `context.Context` first parameter that `sdk#288` added to the
`deploykit` deploy-config family, unblocking `charly`'s bump to `sdk
v0.2026272.1813` (the prerequisite for the `#717` fix; see
[opencharly/charly#738](https://github.com/opencharly/charly/issues/738)).

Against `sdk v0.2026272.1813` this module previously failed to compile:

```
./status_flat.go:206:70: not enough arguments in call to deploykit.ResolveBoxEngineForDeploy
	have (string, string, string)
	want (context.Context, string, string, string)
```

Change — thread the plugin's **real** per-invocation ctx (no fabricated
`context.Background()`):

- `status_flat.go:206` — `collectSingle` passes its own `ctx` (the status
  fan-out's ctx, which reaches it through `collectWord`/`collectFlat`) into
  `deploykit.ResolveBoxEngineForDeploy(ctx, …)`.

The bump also advances `spec` (via `sdk`) to `v0.2026272.1512`, whose
venue-trait model changed `deploykit.FindVmDeployNode` to identify a host-libvirt
vm by the loader-**stamped** `node.Descent` trait (`deploy.IsVmVenue`) instead of
the unpersisted `target:` word (and dropped the `vm:<name>` key fallback). The
`enrichVmRow` test fixtures still built the old word-shape nodes, so they are
stamped with `spec.DescentFromTraits(&spec.DeployTraits{Venue:"ssh",
MachineVenue:true, ExclusiveVenue:true})` — the exact shape a `LoadUnified`'d
project / per-host overlay read produces (`loaderkit.StampDeployDescents`), and
mirroring the sdk's own `deploy_state_test.go` `vmDescent()` helper. `charly.yml`
and the plugin entity are untouched.

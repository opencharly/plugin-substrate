# 2026.318.1711 — test(vm): move the mcp_provide and krun-defaults tests with the body

## Summary

opencharly/spec#304 unit 8, the rest of the coverage. Two more behaviour tests of the vm body still compiled `spec` shipped schema and its generated `spec.Vm`. They move HERE, before the contract leg deletes `#Vm`:

- `TestVm_MCPProvideSchemaParse` - the mcp_provide gate over the composed `#Vm`: a body with two entries parses, an entry without transport defaults to http, and an entry missing `url` is REJECTED (proving the field binds `#CandyMCPProvide`, not an open passthrough).
- `TestVmKrunDefaultsMaterialize` - the krun block required-with-default fields carry the measured values in the VALUE (a concrete validation), not in a consumer-side literal.

**One test stays behind with its subject:** `TestVm_MCPProvideYAMLRoundTrip` asserts the deleted `spec.Vm` Go type, and the envelope does not replace it (mcp_provide is the authored body own field, carried as opaque bytes). Its schema half is covered by the parse test moved here.

**The harness:** both tests sit on the composed unit (the spec base and this plugin served unit). TestVm_MCPProvideSchemaParse takes it via composedBodySchema(t) directly; TestVmKrunDefaultsMaterialize takes it via composedVm(t), the small helper vm_body_test.go added in plugin-substrate#43 (it returns the #Vm def plus the context so a test can compile literals in the def own context).

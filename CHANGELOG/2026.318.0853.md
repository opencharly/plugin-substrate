# 2026.318.0853 — test(substrate): move the firecracker body's tests with the body

## Summary

`opencharly/spec#304` unit 7, the coverage half of the cutover. The `firecracker` body lives in this plugin's CUE module (moved by `opencharly/plugin-substrate#40`), and its **five `#FirecrackerValue` validation tests** still compiled `spec`'s shipped schema. They move HERE — **before** the contract leg deletes the defs — so the coverage never lapses.

The five properties, unchanged: a realistic template (host surface + microVM + runner pool) is accepted; the **host-only** form (no `image`) is accepted, because that is the host profile a deploy inherits from; a required scalar is enforced; an unknown key is rejected (the def is CLOSED); and the `containerd.snapshotter` enum rejects a mount-backed value that cannot back a microVM root drive.

**Both the harness and the COMPLETENESS check are the point.** The harness composes exactly what the host's gate composes (`composedBodySchema` = base & served unit), and every acceptance check asserts `cue.Concrete(true)` — plain `Validate()` treats a missing required field as *incomplete* rather than erroneous and would report success, and a positive gate that cannot fail is not a gate (R7).

**A defect the move fixed rather than carried:** two of the moved tests built their literal with a fresh `cuecontext.New()`. Against the shipped schema that worked by accident; against a composed unit it unifies values from two contexts and fails with an empty-disjunction error that names nothing (the lesson the kubevirt tests paid for). Both now compile in `v.Context()`.
